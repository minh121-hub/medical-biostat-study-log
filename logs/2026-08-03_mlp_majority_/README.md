# MLP & Majority Class Trap
 
## 뭘 했나
 
기존에 쓰던 합성 임상 데이터(age, bmi, smoking, systolic_bp → outcome, n=150)로 MLPClassifier를 학습시켜봤다. 은닉층 구조를 (10,)과 (5,5)로 바꿔가며 비교.
 
## 뭐가 나왔나
 
- (10,) 구조: test accuracy 0.667
- (5,5) 구조: test accuracy 0.667 — 완전히 동일
구조를 바꿔도 결과가 똑같이 나온 게 이상해서 confusion matrix로 확인해봤다.
 
```
              예측=0   예측=1
실제=0(10명)    0        10
실제=1(20명)    0        20
```
 
예측이 전부 1로만 나오고 있었다. 즉 모델이 아무것도 학습하지 못하고 다수 클래스(outcome=1, 전체의 약 60%)만 찍고 있었던 것. accuracy 0.667은 그럴듯해 보였지만 실제로는 아무 의미 없는 숫자였다.
 
`cross_val_score`로 5-fold CV를 돌려서 재확인:
 
```
[0.6, 0.633, 0.633, 0.633, 0.533]
평균: 0.607
```
 
단일 split(0.667)보다 낮게 나왔고, fold마다 큰 변동 없이 다수 클래스 비율과 비슷한 수준에 계속 수렴하고 있었다. 이게 바로 "학습이 안 되고 다수 클래스만 찍는다"는 걸 뒷받침하는 증거.
 
## 배운 것
 
1. **모델을 복잡하게 만든다고 항상 좋아지는 게 아니다.** n=150처럼 작고 신호가 약한 데이터에서는, 파라미터가 많은 MLP가 오히려 아무 패턴도 못 찾고 다수 클래스로 도망가는 방향으로 수렴할 수 있다.
2. **accuracy 하나만 보면 이런 함정을 못 잡는다.** confusion matrix를 직접 까봐야 "다 1로 찍고 있다"는 게 드러난다.
3. **단일 train/test split은 신뢰할 수 없다.** CV를 돌려보니 단일 split보다 낮고 안정적으로 낮은 수치가 나와서, 우연히 잘 나온 숫자였다는 게 확인됐다.
## 다음에 해볼 것
 
- class_weight='balanced' 옵션으로 소수 클래스도 신경 쓰게 만들면 결과가 바뀌는지 확인
- 데이터 자체(n, 신호 강도)를 키웠을 때도 같은 함정이 재현되는지 비교
